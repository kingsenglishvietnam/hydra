## Findings worth keeping

**`gdi_graphics_pipeline_init_ex` does not install an EndPaint.** The captured
pointer was `0000000000000000`. The comment in the old code — "gdi installs its
own when the channel connects" — was wrong, and the bisect built on it meant
nothing published via EndPaint under gfx at all. Frames were arriving through
`hydra_begin_paint` chaining instead.

**Coalescing collapsed, which is the codec working.** Before the EndPaint fix:
1215 paints / 163 published / 1052 coalesced. After: 236 / 165 / 71. Same
publish rate, far fewer redundant paints — larger, fewer damage regions, which
is what a codec stream looks like against raw region updates.

**`desktop resize` fires more than once per session**, not just at attach. The
null callback was going to be hit repeatedly, not once.

## Traps, so they are not hit a third time

- `hydrardp <seat> <user> [password] [host]` — `argv[3]` is the **password**.
  The gfx switch is the **`HYDRA_GFX` env var**, never a command-line flag.
  Passing `/gfx:RFX` positionally sends it as the password.
- A running `hydrardp` locks `dist\hydrardp.exe`; the compile then succeeds
  while the link fails with `Permission denied`, leaving a **stale binary**.
  Always check `LastWriteTime` on the exe against the source.
- Logs under `C:\ProgramData\Hydra\logs` are **startup-only**. Check
  `LastWriteTime` before believing any of them. `hydra-shm.ps1` reads live
  state from shared memory instead — run it elevated.
- `hydractl status` needs an elevated shell or returns `err 5`.
- `Tee-Object` buffers; a run that looks silent may just be unflushed.
