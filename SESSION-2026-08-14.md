## 2. VERIFIED WORKING — use the launchers, never raw invocations

```powershell
.\hydra-start.ps1 -Client mstsc     # mode 1
.\hydra-start.ps1                   # mode 2  -- teach on this
$env:HYDRA_GFX='RFX'; .\hydra-view.ps1 -Desktop 2   # mode 3
```

What the launchers encode that raw invocations lose:

- **`/sound`** — creates the seat's audio endpoint. Without it `abcap` fails
  `0x80070490` forever and there is no sound in any mode.
- **client parking** — 320x200 topmost thumbnail. A covered client stops
  requesting updates and the panel freezes (Suppress Output PDU).
- **start order + frame wait** — service, then client, then mirrors. A mirror
  started against an empty ring sits at ~7 MB showing nothing.
- **`hydra-view.ps1` starts BOTH mirrors** (fullscreen on DISPLAY2 + a windowed
  one). `STATE.md` check: two processes, 70–98 MB each.

`HYDRA_GFX`: `RFX` works. **Never `1`** — the server picks H.264 and this
`WITH_VAAPI_H264_ENCODING=ON` build crashes. Unset/`none` = plain bitmap updates,
which *looks* like a glitch bug and is not.

`display_mode` must match: **`capture`** for modes 1–2, **`client`** for mode 3
(client creates the shared sections but launches no capture agent, so `hydrardp`
is the only producer — `c18600d`).

Manual mode 3, from `STATE.md`, two shells:

```powershell
cd C:\Programs\hydra; Start-Service Hydra; Stop-Process -Name session_capture -Force -EA SilentlyContinue; $env:HYDRA_GFX='RFX'; .\dist\hydrardp.exe B teacher
```

```powershell
cd C:\Programs\hydra; Get-Process mirror -EA SilentlyContinue | Stop-Process -Force; Start-Process '.\dist\mirror.exe' -ArgumentList 'B','\\.\DISPLAY2' -WindowStyle Minimized; Start-Process '.\dist\mirror.exe' -ArgumentList 'B','--window','1600x900','56789'
```

Full stop, always:

```powershell
Get-Process mirror, hydrardp, sdl-freerdp, mstsc, cursor_overlay -EA SilentlyContinue | Stop-Process -Force; Stop-Service Hydra; query session
```

then `logoff <teacher id>`. **Never run two modes at once** — two clients on one
session, or two producers on one ring, wedges the RDP stack and costs a reboot.

## 4. MODE 4 — `0xD000000D`, and it is close

Provider (`HydraProto`) works: creates a real logged-in session with no RDP in
the path. Driver package installs cleanly. The failure is narrow and now pinned.

WUDF operational log (**off by default** — `wevtutil sl
Microsoft-Windows-DriverFrameworks-UserMode/Operational /e:true`) gives the exact
sequence:

```
1003 Driver Manager starts host for SWD\REMOTEDISPLAYENUM\HYDRASEAT_REMOTEIDD_V1&SESSIONID_000n
2003 host asked to load drivers
2010 host SUCCESSFULLY loaded drivers for the device
2004 host loading driver 'iddseatremote' at level 0
2005 host loaded WUDFx02000.dll
2007 FAILED to load driver at level 0, error 3489660941 = 0xD000000D
2900/2901/1006/1008 host shuts down
```

`iddseat.log` is never created → **`DriverEntry` is never reached**. The
framework is refusing the binary; this is not our code failing.
`setupapi.dev.log` agrees: package configures cleanly, RD stack creates the
devnode, then `CM_PROB_FAILED_ADD (0x1f)` status `0xc0000001` after ~958ms.

**Eliminated:** IddCx version (1.11→1.10); UMDF version (2.35 and 2.33 share one
runtime — `WUDFx02000.dll` is the UMDF 2.x host for every minor version, so this
was never the variable); signing; wrong binary staged (DriverStore hash matches
`dist\driver-remote`, differs from `dist\driver`); exports (`FxDriverEntryUm`
present, correct); `UmdfHostProcessSharing` (was missing despite the INF comment
and `eed4f63` claiming otherwise — added `ProcessSharingDisabled`, still fails,
BUT `PreDisconnect` moved from `reason=17` at 1.2s to `reason=12` at 33s);
`UmdfKernelModeClientPolicy=AllowKernelModeClients` (removed).

**Next instrument, not yet used:** the WUDF **framework verifier**, which logs
*why* a driver was rejected rather than only that it was.

**Also found:** RDP-Wrapper and HydraProto are **mutually exclusive**. With
`rdpwrap.dll` as `TermService`'s `ServiceDll`, `TestProtocol_Ext.dll` never loads
and the `hydraproto` listener never appears. Point `ServiceDll` at stock
`termsrv.dll` and both appear immediately. Clean A/B. New since the wrapper
became `type= own`.

**Traps:** `-Register` recreates the listener key EMPTY, so credentials must be
re-set every time (`Username=teacher`, `Domain=''`, `Password`). Stale
`SessionId` devnodes in `CM_PROB_FAILED_ADD` block retriggering — reboot between
attempts. A registered provider locks its own DLL: unregister → build → register.

Emergency undo if the provider takes RDP down:

```
reg delete "HKLM\System\CurrentControlSet\Control\Terminal Server\WinStations\HydraProto" /f
sc stop TermService
sc start TermService
```

## 6. SAFETY — one change per reboot

`safety-gate.ps1` verifies three levels of undo before any boot-risk operation
and refuses if any is missing: **cwd** (driver-store snapshot + generated
`undo-online.ps1` + captured class filters), **WinRE** (`reagentc` enabled AND
`bootstatuspolicy` not `ignoreallfailures`), **USB** (tested bootable stick with
`UNDO-OFFLINE.txt` on it). Level N is only a real undo if level N+1 exists; on
08-12 all three were gone at once.

**CBS transactions are staged in `WinSxS\pending.xml` and applied in EARLY
BOOT** — before the shell, before the dump stack, and Safe Mode processes them
too. A failed transaction retries every boot and cannot be reached from a running
OS. `revertpendingactions` returning `0x800f082f` means CBS cannot unwind it.
Renaming `pending.xml` is the crude escape.

The 08-12 boot carried **four** first-time changes at once: `testsigning` newly
set and never booted, a staged driver package, `DenyUnspecified=1` machine-wide
device policy, and a registered protocol provider. When it failed there was no
way to tell which — and the logs that would have said were destroyed by the
reset (`setupapi.dev.log`, `CBS.log`, `System.evtx` are NOT in `Windows.old`).

**Rule: one boot-affecting change, reboot, verify, then the next.**

Cleared under controlled conditions since: the driver package alone does not
brick the machine; Interception does not cause activation timeouts.

Recovery stick (E:, FAT32, RECOVERY) now holds: full Windows recovery image,
`hydra-repo.bundle` (`git bundle --all`), `hydra-dist\`, `rdsprov\`, `safety\`,
`UNDO-OFFLINE.txt`, `class-filters.json`, and all four `.md` docs.
