## 1. THE GLITCHY CURSOR — SOLVED, it is input forwarding

Not `agent:B`, not err 5, not the codec. `MODES.md` says it outright, and Nathan
found it empirically before I read it:

> If your cursor reaching that thumbnail moves the seat's cursor, the window is
> forwarding your input — move it out of the way.

Two windows forward console input into seat B:

- `hydra-start.ps1` parks the client as a **TopMost 320x200 thumbnail, TopRight**
- `hydra-view.ps1` starts a **windowed mirror with input forwarding on**

The seat panel is to the **right** (DISPLAY2 at 3240,0), so a TopRight thumbnail
sits directly on the path between the two screens. Every trip across it forwards
input. That is why Nathan's workarounds — putting the mini window on VD2 only, or
the seat-1 mirror on VD1 — both help.

**Fix:**

```powershell
.\minify-mstsc.ps1 -Process sdl-freerdp -TopMost -Width 320 -Height 200 -Corner BottomLeft
```

`BottomLeft`, away from the crossing. For mode 3 the equivalent is
`hydra-view.ps1 -Desktop 2`, or move the windowed mirror by hand.

**The real fix is still PROBLEM 4** — monitor separation. `NEXT-STEPS.md` §3:
drag the seat monitor **above** the console monitor in Settings, offset sideways
so only a couple of hundred pixels of edge touch. Currently 2314px apart and side
by side; it was ~8100px (`0,0` and `11340,0`) before the reset. Two minutes, and
it removes the crossing entirely.

**The client window must never be COVERED or on an inactive virtual desktop** —
it stops requesting updates, the seat's desktop stops being composed, and the
panel freezes on a stale frame. Measured with both mstsc and sdl-freerdp.
`hydra-start.ps1:345` has the full comment.

## 4. FIXES APPLIED THIS SESSION

**`audio-pin.ps1`** — `-Apply` failed with *"RegistryKey.SetValue does not
support arrays of type 'Object[]'"*. Two bugs on one line: `-Path` treats `[`,
`]`, `?` as wildcards and audio endpoint key names are full of them; and
`$e.Value` is not guaranteed to be a string after a JSON round-trip. Now
`-LiteralPath` + `[string]` cast + `-Type String` on lines 91/97/98.

**`hydra-start.ps1`, `hydra-view.ps1`** — `Import-Module VirtualDesktop` now
passes `-DisableNameChecking`. Cosmetic only; `Pin-Window` resolves correctly
(VirtualDesktop 1.5.11).

**`hydra-view.ps1`** — PS 7.4 turned on `$PSNativeCommandUseErrorActionPreference`
by default, so native-command stderr honours `ErrorActionPreference`. `mirror`
writes its *success* message `[mirror] pixel transport opened` to stderr, and
`2>&1` under `'Stop'` made it terminating. Bracketed with `Continue` around the
`--probe` call.

**`build-driver.ps1`** — added the explicit `UmdfLibraryVersion` substitution
`1427b7a` asked for. Substitutes in the copied INF, keyed to `$umdf` so it cannot
drift from what the DLL links against. `dist\driver` no longer ships the literal
token.

**`seats.toml`** — `audio_bridge` GUID → `3012a3df`, comment table → `969db10d`,
`confine_monitor` commented out.

## 9. SAFETY — one change per reboot

`safety-gate.ps1` verifies three undo levels and refuses if any is missing:
**cwd** (driver-store snapshot + generated `undo-online.ps1` + class filters),
**WinRE** (`reagentc` enabled AND `bootstatuspolicy` not `ignoreallfailures`),
**USB** (tested bootable stick with `UNDO-OFFLINE.txt`). Level N is only real if
N+1 exists; on 08-12 all three were gone at once.

CBS transactions stage in `WinSxS\pending.xml` and apply in **early boot** —
before the shell, before the dump stack, and Safe Mode processes them too.
`revertpendingactions` returning `0x800f082f` means CBS cannot unwind it.

The 08-12 boot carried **four** first-time changes at once. When it failed there
was no way to tell which, and the logs were destroyed by the reset
(`setupapi.dev.log`, `CBS.log`, `System.evtx` are NOT in `Windows.old`).

**Rule: one boot-affecting change, reboot, verify, then the next.**

Recovery stick (E:, FAT32, RECOVERY): full Windows recovery image,
`hydra-repo.bundle`, `hydra-dist\`, `rdsprov\`, `safety\`, `UNDO-OFFLINE.txt`,
`class-filters.json`, and the docs.
