## What was found today

**PROBLEM 2 root cause: `update->DesktopResize` was NULL.**

`gdi_graphics_pipeline_init` sends ResetGraphics when the channel attaches, the
server answers with a desktop-size notification, and libfreerdp calls
`update->DesktopResize(gdi->context)` having checked only that `update` itself
is non-NULL. Disassembly at `libfreerdp3.dll+0xDCB4B`:

```
test %r14,%r14          <- checks the struct
je   ...
mov  (%r12),%rcx        <- r12 = gdi, *gdi = gdi->context
call *0x68(%r14)        <- does NOT check the slot
```

`offsetof(rdpUpdate, DesktopResize)` == `0x068`, one argument, returns BOOL.
Confirmed by compiling `rdp/offs.c` → `dist/offs.exe`.

`CacheImportOffer` also sits at `0x68` in `RdpgfxClientContext`, but it takes
two arguments and the second register is never loaded. Not it.

Without `/gfx` that path never runs — which is why every non-gfx run was clean
and eleven hypotheses (codec, double channel init, pointer registration,
EndPaint chaining, channel interception, context layout, SoftwareGdi, thread
affinity, pipeline init stubs) all missed it. None of them looked at
`rdpUpdate`.

**How it was found:** `rdp/hydra_veh.c`, a first-chance vectored exception
handler included from `hydrardp.c`. On the AV it dumps `[rsp+00]` resolved to
module+RVA. The `call` pushes its return address before faulting, so that value
names the caller. One run, no hypothesis.

**Fix applied:** `hydra_desktop_resize()` in `hydrardp.c` ~line 691, assigned at
~line 710 before the paint callbacks. Patch script: `fix-desktopresize.ps1`
(`-Revert` restores the newest `.bak-*`).

## Traps hit today, worth not repeating

- `hydrardp <seat> <user> [password] [host]` — `argv[3]` is the **password**.
  Passing `/gfx:RFX` there sent it as the password → `ERRCONNECT_LOGON_FAILURE`.
  The gfx switch is the **`HYDRA_GFX` env var**, not a command-line flag.
- `Tee-Object` buffers; a run that looks silent may just be unflushed.
- A running `hydrardp` locks `dist\hydrardp.exe` — the linker then fails with
  `Permission denied` while the compile succeeds, leaving a stale binary.
- Logs in `C:\ProgramData\Hydra\logs` are **startup-only**. `capture_B.log`
  ends at "entering capture loop"; `router.log` stops early. Check
  `LastWriteTime` before reading any of them as current state.
- `hydractl status` needs an **elevated** shell or returns `err 5`.
